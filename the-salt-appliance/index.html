How to use the Salt Appliance OVA

v0.10.0

The basic overview

  1. Deploy the OVA
  2. Login
  3. VMware appliance credentials input
  4. Review sample Salt state files (provide specific functionality)
  5. Run Salt commands to perform the task.

Step by Step

1. Deploy the OVA

Deploy the OVA in your environment with the defaults. It needs an IP that can reach the VMware appliances you want to reach. It will pick up a dynamic IP by default so change it to a static one if you need to.

2. Login

  1. Credentials are username: root with password: shessalty. You will be prompted to change the password upon successful login.
  2. It is highly recommended that you run tdnf update to update the Photon OS with the latest patches.
  3. Salt Master 3008.2, Salt Minion 3008.2, and the Salt Extensions for VCF are already installed. You can check the Salt version by running the following commands:
    • salt-master --version
    • salt-minion --version
  4. Two directories that are required by Salt Master were created:
    • /srv/pillar — in this example use case, this directory will hold the credentials to your target VCF Appliances.
    • /srv/salt — this is the default location where Salt Master holds the Salt State files. Salt state files are text based files where you document your desired values for configuration settings (for this example).

You can navigate into those directories to view the example files that have been created for your use. You will need to edit those files for your environment next.

3. Modify the sample default files with your VMware appliance credentials

Navigate to /srv/pillar and view the example files:

FileDescription
vcfcredentialspillar.slsThis system is designed to use this file as the default file containing credentials to your VCF environment. You will edit this file in order to configure Salt to access your VCF appliances.
vcfcredentialspillar-reference.slsIf you are unsure of any changes in the default vcfcredentialspillar.sls file, you can refer to this file for reference.
vcfcredentialspillar-EXAMPLE.slsDuring my testing, besides the actual password, these were the settings I used to successfully use Salt with my VCF instance.

All example files provided in /srv/pillar and /srv/salt adhere to Salt’s required formatting and syntax. If you deviate from this format, Salt will not be able to parse, read, and use the file.

Edit the vcfcredentialspillar.sls file and add the username and password to the VCF components you would like to target. Comment out any components you do not intend to use.

Here is an example of the contents of the vcfcredentialspillar.sls file:

saltext.vcf:
  vcenter:
    host: myfqdn.myorg.com
    username: administrator@vsphere.local
    password: yourpasswordhere
    verify_ssl: false

  sddc_manager:
    host: myfqdn.myorg.com
    username: administrator@vsphere.local
    password: yourpasswordhere
    verify_ssl: false

  nsx:
    host: myfqdn.myorg.com
    username: admin
    password: yourpasswordhere
    verify_ssl: false

  vcf_ops:
    host: myfqdn.myorg.com
    username: admin
    password: yourpasswordhere
    verify_ssl: false

Please keep in mind that this ova and the Salt components in this installation are designed to use the credentials outlined in the vcfcredentials.sls file. If you use a different credential for the appliances, they may not work.

Important: It is recommended that you issue the following command in order to ensure the Salt system is refreshed to use your credentials:

salt-call saltutils.pillar_refresh

*Important Note: It is recommended to encrypt any files you store sensitive credentials or important data. Since this system is being offered as a proof of concept for functionality, clear text files are being used to reduce the complexity of the environment.

4. Review sample Salt state files

Modify the sample Salt state files that contain the settings you want to monitor for.

All example files provided in /srv/pillar and /srv/salt adhere to Salt’s required formatting and syntax. If you deviate from this format, Salt will not be able to parse, read, and use the file.

Navigate to /srv/salt and review the sample files included:

FileDescription
checkpwexpire_AllVCF.slsThis state file will return all local accounts on VCF with passwords that will expire within 90 days. The expiration length of 90 days is modifiable in the file. This file will only return the requested data.
dns_VC.slsThis file will compare the dns server setting in vcenter against the dns server listed in this file (8.8.8.8 is in the file as a default). This file will tell you whether the target vcenter is using the designated dns server. This file can also apply the dns server setting on vCenter if it does not match the dns setting in the file.
list_local_users_ALL_VCF.slsThis file will return all local users from all VCF appliances. This file will only return the requested data.
list_local_users_NSX.slsThis file will return all local users from NSX appliances. This file will only return the requested data.
list_local_users_VC.slsThis file will return all local users from vCenter appliances. This file will only return the requested data.

These sample Salt state files are intentional in their simplicity and are meant to demonstrate the basic Salt constructs needed to perform operational VCF Tasks. Salt is capable of significantly more complex logic via the Salt state files, jinja files, top files, etc. However, the more advanced Salt capabilities are beyond the scope of this post.

5. Run Salt commands to perform the task

Execute a Salt state file to perform the designated task in the state file.

FileCommands
checkpwexpire_AllVCF.slsAt the command line of the system:
salt '*' state.apply checkpwexpire_AllVCF

If you want to capture the return in a file, direct the return to a file:
salt '*' state.apply checkpwexpire_AllVCF > /tmp/checkpwexpire_AllVCF_output.txt
dns_VC.slsAt the command line of the system:
salt '*' state.apply dns_VC test=True

To update the vCenter's dns settings with what is in the dns_VC.sls file, issue the following command:
salt '*' state.apply dns_VC
list_local_users_ALL_VCF.slsAt the command line of the system:
salt '*' state.apply list_local_users_ALL_VCF

If you want to capture the return in a file, direct the return to a file:
salt '*' state.apply list_local_users_ALL_VCF > /tmp/list_local_users_ALL_VCF_output.txt
list_local_users_NSX.slsAt the command line of the system:
salt '*' state.apply list_local_users_NSX

If you want to capture the return in a file, direct the return to a file:
salt '*' state.apply list_local_users_NSX > /tmp/list_local_users_NSX_output.txt
list_local_users_VC.slsAt the command line of the system:
salt '*' state.apply list_local_users_VC

If you want to capture the return in a file, direct the return to a file:
salt '*' state.apply list_local_users_VC > /tmp/list_local_users_VC_output.txt

If you want to see what else is possible with the modules on the OVA, visit the saltext-vcf page.
